# 水电站机组运行检修管理平台

面向电站台账、机组运行、调速励磁、主变与闸门、大坝渗流位移监测、机组检修与发电计划的一体化水电站运行检修管理平台。

这是一个**纯前端**管理平台：Vue 3 + Vite + TypeScript，仓库里没有后端服务。业务数据由
`frontend/src/data/` 下的本地数据层提供：首次打开用示例数据播种，之后的登记、筛选与状态流转
结果都持久化在浏览器 `localStorage` 里，刷新或重开浏览器都还在。dev server 已关掉自动打开页面，
启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端（唯一运行单元）
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/local-service.ts   本地数据服务：列表、筛选、动作流转、导出
│   ├── src/data/             模块元数据 / 示例数据 / localStorage 持久化
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false，无 /api 代理）
├── .gitignore
└── docker-compose.yml
```

## 启动

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，需要自己访问。

生产构建：

```bash
cd frontend
npm run build
```

业务规则验证（不需要浏览器，内存 localStorage 里跑完整数据流）：

```bash
make verify
```

覆盖：确认清污时压差/优先次序/待清理台数同口径重算、重复确认幂等、重复报送退回仅留痕、
存量清污与保护台账按日期回填、落库失败整套回滚、跨模块台数对账。

## 约定

- 每个模块的页面在 `frontend/src/views/<模块>/index.vue`，页面只负责渲染，读写统一走
  `frontend/src/api/local-service.ts`。
- 字段、状态、动作与流转目标集中在 `frontend/src/data/modules.ts`；示例数据在
  `frontend/src/data/seed.ts`。
- 状态流转只允许在 `local-service.ts` 里改，页面组件不做业务判断。
- 想回到初始数据：清掉浏览器里 `hydropower-plant-om:entries` 这一项，或调用 `resetModule(模块)`。

## 拦污栅清污（同一份口径）

- 压差、超限（阈值 1.50m 水柱）、清污优先次序、待清理台数全部由
  `src/domain/trashrack.ts` 计算；栅体列表（`/trashrack`）、清污次序页
  （`/trashrack/cleaning`）、另存的清污清单、运营概览读的是同一份数据。
- 「确认完成」在一个事务里同时完成：状态置已清理、前后压差重算为残余值 0.10m、
  清污次数加一、追加一条清污日志、栅体移出待清理队列。落库失败整套回滚，不留半条记录。
- 已清理栅体重复确认直接拒绝，不加次数、不写日志。
- 历史清污按清理日期回填（相邻清污按 45 天倒推）；早于平台上线日 2026-09-01 的标记
  「存量补录」，清理日期缺失的不虚构记录，以备注注明待查纸质台账。

## 继电保护运行台账（结论唯一来源）

- 设备状态以 `src/domain/protection.ts` 运行台账中最新一条「受理」校验结论为准，更早的
  结论仅留痕；运行台账页在 `/protection/ledger`。
- 同装置、同记录时间、同结论重复报送只算一次：后到一份记「退回」，仅留痕，不改设备、
  不进统计。
- 存量台账按记录时间回填；上线前校验记录缺失的登记一条「缺项说明」，装置按待校验跟踪，
  不编造历史结论。
- 台账涉及装置数、设备台账在账数、运营概览登记数三处同口径，台账页底部有对账提示。
